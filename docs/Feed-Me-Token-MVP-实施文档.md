# Feed Me Token：MVP 实施文档

> 版本：v0.1（2026-09-28）。依据 [MVP 设计草案](./Feed-Me-Token-MVP-设计草案.md) 与 [角色美术设定](./Feed-Me-Token-角色美术设定.md)。本文维护当前目标与规则；历史决策、实现状态及验证结果见 [开发记录](./开发记录.md)。

## 1. 交付目标

交付 Windows 与 macOS 的桌面常驻小游戏。应用只读本机 Codex 用量记录；首次启用从零结算，此后新增 token 从左侧管道进入生产机，产出的能量棒在机器与主角之间堆积。三头身贪吃小女孩从堆里取棒吃下、伸手发射短促能量射线，击败显示器头机器人，获得金币和经验，使用金币升级攻击。应用能隐藏、重启并恢复进度。

MVP 只支持 Codex。Cursor 与 WorkBuddy 留在后续阶段，先核实其真实 token 记录或官方接口。

## 2. 技术结构

| 层 | 技术 | 职责 |
| --- | --- | --- |
| 桌面外壳 | Tauri 2 | 透明无边框窗口、置顶、拖动、托盘、跨平台打包。 |
| 本地数据 | Rust | 只读发现与解析 Codex 记录、计算新增 token、维护结算检查点、原子保存状态。 |
| 游戏与界面 | TypeScript | 战斗状态机、数值与交互、HUD、设置面板。 |
| 绘制 | PixiJS | 生产机、管道、能量棒堆与取棒动作，以及皮肤精灵、短射线、命中乱码、奖励动画。 |

建议目录：`src-tauri/src/usage/`（Codex 适配器及结算）、`src-tauri/src/state/`（持久化）、`src/game/`（纯战斗规则）、`src/render/`（PixiJS 场景）、`src/ui/`（HTML/CSS 面板）、`assets/`（精灵表、图标及可编辑源文件）。具体目录可随脚手架调整，但数据读取与渲染边界保留。当前原型的美术资源实际位于 `app/public/skins/`，由 `app/src/skins.ts` 加载；资源包格式见[皮肤资源说明](./皮肤资源说明.md)。

Rust 向前端暴露少量命令：获取状态、刷新用量、保存游戏动作与更新设置。用量检查点、兑换余数和新增能量必须在一次持久化操作中更新；游戏动作在动画确认完成时保存。任一步失败时保持旧状态，下一次刷新可重试。前端不接收或存储 Codex 提示词正文。玩法数值、动画节奏与预览参数以 [`app/game-config.json`](../app/game-config.json) 为单一来源，两端在构建时嵌入，详见[配置说明](./配置说明.md)。

## 3. Codex 数据接入

1. 参考 ccusage 的 Codex 适配器，核实 Windows/macOS 上 Codex 桌面应用与 CLI 的本地记录路径及实际 token 字段。优先支持用户配置的 `CODEX_HOME`，再检测默认位置；不得扫描无关目录。
2. 只读处理用量事件，忽略对话内容。统一输出会话标识、记录时间、累计/增量 token 分类与稳定事件标识。异常行、正在写入的不完整行可跳过并在下一轮重试。
3. 初次启用扫描当前可见记录并建立基线，游戏累计 token、能量棒、金币和经验从 0 开始。关闭应用期间产生的新用量在下次启动时补结算。
4. 对同一会话的累计报告只兑换正向新增量；刷新、重启、文件回退、重复事件、跨日与桌面/CLI 重合记录不得重复结算。
5. MVP 兑换口径取 Codex 报告的 `total_tokens` 增量；缓存 token 若已包含在该总数中，不再单独相加。技术小样须用真实样本和 ccusage 的 Codex 统计结果核对口径，若字段语义不同则修订本文。
6. 每 60 秒自动刷新一次，可手动刷新。读取错误显示在状态面板，不以估算值发奖；离线环境仍可读取已有记录。

来源接口保留 `discover`、`readNewUsage`、`health` 三类职责，MVP 仅实现 Codex。Cursor/WorkBuddy 后续各自实现，不与 Codex 解析逻辑耦合。

## 4. 游戏规则与状态

以下数值是首轮试玩基线，已集中在 `app/game-config.json`，试玩后可调整。规则变动时需明确存档兼容方式；改动需重新构建程序，不会自动重算已有存档。

| 规则 | MVP 值 |
| --- | ---: |
| 兑换 | 1,000 个新增 `total_tokens` → 1 根能量棒，余数结转 |
| 攻击 | 自动消耗 1 根棒，造成初始 1 点伤害 |
| 怪物生命 | `1 + floor((波次 - 1) / 20)`；前 20 波默认一击倒下 |
| 击败奖励 | 1 金币、3 经验 |
| 升级经验 | 当前等级 × 10，自动升级，剩余经验结转 |
| 攻击升级 | 初次 5 金币；价格为当前攻击力 × 5；攻击力 +1 |

画面从左到右为 token 输入管道、生产机、能量棒堆、主角与机器人。每次刷新发现新增 token 时，输入粒子沿管道进入机器；凑满 1,000 token 后，机器向堆放区送出能量棒，不足部分只更新机器进度条。一次刷新产出多根时，前四根逐一表演，更多产出合并为一次入堆，以免长时间回放。重启后已有库存直接显示在堆中，不重播过去的生产过程；堆的图形最多显示九根，控制栏数字显示准确库存。生产动画未完成的能量棒暂不供主角取用，但兑换和库存已由 Rust 存档结算，关闭或重启不会损失。

机器人每波从画面右边走入，约 1 秒后停在射程内；入场期间不受攻击。堆中有能量棒时，角色按“伸手取棒 → 咬下并鼓腮 → 咽下蓄光 → 伸手射线 → 命中乱码”的顺序攻击；拿在手中的棒暂从堆里扣除，攻击确认后再从存档库存扣除。下一次攻击等前一轮反馈结束。机器人生命归零后屏幕熄灭并淡出约 0.3 秒，发放奖励，下一只随即从右侧走入。没有能量棒时，已入场的敌人与角色待机；MVP 没有玩家生命、失败惩罚和离线战斗模拟。旧存档中的当前敌人生命会下调到新波次上限，不重置其他进度。

存档至少包含：启用时间、Codex 结算检查点、已兑换 token、兑换余数、能量棒库存、金币、经验、等级、攻击力、当前波次、当前怪物生命、窗口位置与设置。重启后可从待机/战斗安全状态恢复，不必恢复动画的中间帧。

## 5. 窗口与交互

- 当前逻辑画布为 320×128，以 2 倍渲染分辨率显示在约 640×320 的窗口中；像素图集采用最近邻采样，插画动作图集采用线性采样。场景透明，保留窄平台、生产机、能量棒堆、角色、机器人和少量 HUD。
- 顶部不设常驻 UI；用户能拖动战斗场景移动窗口。下方控制栏提供刷新、状态详情、置顶、静音、最小化与退出；托盘提供显示、隐藏及退出。状态面板展示 Codex 状态、启用后 token、上次刷新时间、错误信息和内置皮肤选择。默认皮肤为“插画动作版”；无 `skinId` 字段的旧存档也采用该皮肤，显式保存过的薄荷或蜜桃选择保持不变。皮肤选择在原生存档中保存，浏览器模拟预览使用浏览器本地存储。
- 常驻 HUD 展示能量棒、金币、等级及升级入口。中文文字用系统字体或清晰的 UI 字体，不强行栅格化到低分辨率画布。
- 程序音效包含吃棒、射线、命中和奖励的短提示音；提供静音开关。隐藏窗口时暂停绘制，待机时降低更新频率。

## 6. 美术资源与替换边界

首个可玩版本使用原创简化精灵：主角、显示器头机器人、能量棒和平台都要有清楚轮廓，不借用现有游戏素材。正式美术按角色美术设定制作，保持动作名、帧锚点和碰撞/命中位置稳定，便于替换。

当前可玩原型提供“薄荷机房”“蜜桃终端”和“插画动作版”三套内置皮肤。前两套主角采用[已选定概念稿](./art/hero-v1-concept.png)的首轮像素适配，共九个动作姿势；第三套主角使用[六姿势非像素插画图集](./art/hero-v1-illustration-poses.png)，覆盖待机、取棒、咬棒、鼓腮、发射与胜利，受击反馈沿用发射姿势。第三套显示器头机器人使用[四姿势非像素插画图集](./art/robot-v1-illustration-poses.png)，覆盖走入、待机、屏幕乱码受击与关机。主角和机器人在整个战斗循环保持插画风格；生产机与场景仍为像素占位美术。各对象由透明 PNG 图集渲染；第三套另加载角色插画动作图集，清单定义帧范围、动作、脚底锚点、取棒终点、射线起点与机器人屏幕命中点。射线及输入粒子仍由 PixiJS 绘制并读取皮肤颜色。切换皮肤不改玩法状态。新皮肤随应用打包；MVP 暂不从外部目录导入。若存档选择的资源缺失，尝试回退默认皮肤并显示原因。

最低资源：主角待机/取棒/吃棒/射线/胜利，机器人入场/待机/受击/关机，生产机、输入管道、堆放托盘、能量棒、金币、经验图标，一条透明背景上的平台，以及 token 流入、出棒落堆、手掌蓄光、短射线、屏幕乱码、奖励飞出六类特效。特效优先用 PixiJS 图形与粒子绘制；角色动画使用透明 PNG 精灵表。图标需覆盖 Windows 应用图标与 macOS 托盘模板图标。可编辑源文件和导出资源都进入仓库。

## 7. 实施顺序与阶段验收

### 阶段 A：技术小样

- 建立 Tauri 2 + TypeScript + PixiJS 项目，验证 Windows 透明窗口、托盘、拖动与置顶。
- 对 Codex 真实样本建立只读解析小样，确认桌面与 CLI 记录、字段语义、首次基线及增量；加入匿名化测试样本。
- 在真实 Mac 上验证窗口、托盘与 Codex 记录。若暂时无 Mac，明确保留 macOS 验收项，不能以编译通过替代实际验证。

### 阶段 B：可玩循环

- 用开发模式的模拟 token 输入驱动能量棒与完整自动战斗。
- 实现奖励、等级、攻击升级、状态保存及重启恢复。
- 使用简化原创精灵完成吃棒与射线的可读动画。

### 阶段 C：真实数据与完整桌面体验

- 接通 Rust Codex 适配器、自动刷新、异常状态和原子结算。
- 完成 HUD、设置面板、托盘、音效开关及窗口位置保存。
- 替换/完善正式精灵与特效，并在不同壁纸和显示缩放下检查。

### 阶段 D：发行验证

- Windows 与 macOS 构建及运行检查；macOS 包在真实 Mac 上检查签名/公证需求、透明窗口与托盘行为。
- 验证首次零基线、连续刷新不重复、关闭期间新增补结算、日志缺失/损坏、重启恢复、无网络运行。
- 检查待机资源占用和刷新时画面是否卡顿；只针对实测问题优化。

## 8. MVP 完成条件

1. Windows 与 macOS 上，Codex 新用量自动变成能量棒，首次启用的历史用量不发奖。
2. 玩家能清楚看见 token 输入、生产机出棒、库存堆积、主角取棒吃下、伸手射线、机器人屏幕乱码、击败奖励、金币升级的完整循环。
3. 重复刷新或重启不会重复兑换，同一存档可以恢复金币、经验、波次和剩余能量。
4. Codex 不存在、记录异常或网络不可用时，应用仍能启动并说明状态。
5. 常驻窗口能移动、隐藏、置顶和退出；美术在浅色/深色桌面及常见系统缩放下可辨认。

## 9. 当前实现与验证（2026-09-29）

- Windows 版已实现 Codex 本地日志扫描、首次零基线、增量兑换、生产表演、自动战斗、金币与经验、攻击升级、存档、托盘、置顶切换、窗口位置记录和静音开关。主角、机器人、生产机、能量棒、托盘和平台已使用两套可切换的 PNG 图集；主角已有概念稿与首轮像素动作，其他对象仍为占位图。射线和输入粒子仍由程序绘制。应用图标已有原创临时版和可编辑 SVG。
- 本机 Codex 样本确认用量事件路径为 `event_msg → token_count → info.total_token_usage.total_tokens`。抽样的 100 条事件中，`total_tokens = input_tokens + output_tokens` 均成立，`cached_input_tokens ≤ input_tokens` 均成立。因此兑换总量时不再次相加缓存 token。
- 生产表演版本的 `npm run build`、`cargo test --offline`（5 个测试）、Windows release 可执行文件及 NSIS 安装包构建通过；浏览器预览确认下方控制栏、敌人走入、生产机运行、能量棒堆积、取棒吃下和连续推进波次。安装包此前曾因下载 NSIS 3.11 被网络拒绝，开启完整访问后重试成功。旧版发布进程曾在 Windows 桌面会话中启动并迁移旧标识存档；新版原生窗口的画面与按钮交互仍待人工验收。只核对了用量数值，没有读取或展示对话正文。

## 10. 剩余验收

- 在真实 Mac 上运行和打包，检查透明窗口、托盘、Codex 路径、窗口位置和音效。
- 在 Windows 原生窗口中逐项人工检查拖动、置顶、静音、隐藏、浅色与深色壁纸下的可读性；当前环境未完成这些可视交互验收。
- 与 ccusage 的 Codex 统计输出核对同一批日志的 token 总量；目前只核实本机原始字段关系。
- 为插画动作补充过渡帧，制作一致的生产机与场景；检查动作锚点、边缘及不同壁纸的可读性。
