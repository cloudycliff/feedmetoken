# Feed Me Token 皮肤资源说明

皮肤只改变画面，不改变 token 兑换、库存、伤害或存档进度。当前提供“薄荷机房”“蜜桃终端”和“插画小样（待机）”三套内置皮肤。前两套主角已根据[选定概念稿](./art/hero-v1-concept.png)绘制首轮像素动作；第三套在待机时显示该概念稿的透明抠图，动作阶段仍使用薄荷像素帧，用于比较视觉方向。机器人、机器和场景仍是占位美术。游戏内打开底部“数据状态”面板即可切换；原生程序把选择保存在游戏存档，浏览器模拟预览保存在该浏览器的本地存储。

## 资源目录

```text
app/public/skins/
  catalog.json             # 可选皮肤的 ID、名称及默认皮肤
  mint/
    manifest.json          # 帧位置、动作和画面锚点
    sprites.png            # 透明 PNG 图集
  peach/
    manifest.json
    sprites.png
  concept/
    manifest.json          # 薄荷动作图集 + 待机插画配置
    sprites.png
    hero-idle.png          # 由概念图抠出的透明待机图
```

资源随前端一起打包，Windows 与 macOS 共用。已安装的程序不能靠修改源码目录立即增加皮肤；新增或替换资源后需重新构建。当前不支持从用户目录导入外部皮肤。

## 新增或替换一套皮肤

1. 复制一套现有皮肤目录，改为新的小写英文/数字/连字符 ID，并在 `catalog.json` 登记名称与 ID。也可以直接替换现有目录的 `sprites.png` 与 `manifest.json`。
2. 绘制透明 PNG 图集，在 `manifest.json` 的 `frames` 中写入每帧的 `[x, y, 宽, 高]`。每个动作通过帧名列表与 `fps` 选择播放帧；静态图也写成只有一帧的动作。
3. 保留 `girl`、`robot`、`machine` 的动作键，以及 `floor`、`tray`、`bar` 的静态图键。主角需要 `idle/take/eat/beam/hit/victory`；机器人需要 `entering/ready/hit/defeated`；机器需要 `idle/active`。
4. `anchors.girl`、`anchors.robot` 是精灵帧内以像素计的脚底锚点。画面中人物的世界坐标仍由游戏控制；换图时保持脚底、取棒手和发射手的位置与现有画面接近，避免悬空或错位。`effects` 的 `beam`、`token`、`progress` 使用 `#RRGGBB`，分别给射线、输入粒子和机器进度条配色。
5. 在 `app/` 运行 `npm run check:config`，再运行 `npm run dev` 预览。检查浅色、深色桌面背景，尤其是取棒、吃棒、发射、受击与落堆动作。发布版本需重新构建安装包。

若需要单独替换待机插画，可在清单中设置可选的 `idleIllustration: { "asset": "hero-idle.png", "displayHeight": 78 }`。`asset` 是同一皮肤目录内的透明 PNG，`displayHeight` 是其在 320×128 逻辑画布中的高度。待机时使用插画；进入取棒、吃棒或攻击阶段时仍播放该清单中的 `girl` 动作帧。此机制是美术试验入口，不提供完整的非像素动画。

图集按逻辑像素绘制，当前画布为 320×128、渲染分辨率为 2 倍；PNG 使用透明背景。像素图集采用最近邻采样，单独的待机插画采用线性采样。为了让换肤不改变场景坐标，各动作保留固定帧槽：主角 96×80、机器人 64×80、机器 80×64、能量棒 20×10、托盘 40×8、平台 320×16。形象可以在帧槽内重新设计，图集中的摆放位置可变；同一角色的各动作共用脚底锚点。

薄荷与蜜桃图集的可编辑源是 [`app/tools/generate-placeholder-skins.py`](../app/tools/generate-placeholder-skins.py) 与主角绘制模块 [`app/tools/draw_hero_v1.py`](../app/tools/draw_hero_v1.py)，运行前者需要 Python Pillow。插画小样由 [`app/tools/make_illustration_idle.py`](../app/tools/make_illustration_idle.py) 从原始概念图生成透明抠图，并复制薄荷动作图集；该脚本需要 Pillow、NumPy 和 SciPy。生成的 PNG 与清单已提交，普通构建不需要 Python。正式美术可用 Aseprite、LibreSprite 等工具绘制并导出透明图集，保存可编辑源文件。

## 存档与回退

旧存档没有皮肤字段时默认使用“薄荷机房”。切换皮肤只保存 ID，不改玩法资源；如果后续版本移除了某套皮肤或文件损坏，启动时尝试显示默认皮肤，并在状态面板提示原因。内置皮肤切换时会先加载资源、再保存选择；加载失败则保留原皮肤。
