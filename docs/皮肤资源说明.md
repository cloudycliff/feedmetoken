# Feed Me Token 皮肤资源说明

皮肤只改变画面，不改变 token 兑换、库存、伤害或存档进度。当前提供“薄荷机房”“蜜桃终端”和“插画动作版”三套内置皮肤。前两套主角已根据[选定概念稿](./art/hero-v1-concept.png)绘制首轮像素动作；第三套使用[主角六姿势](./art/hero-v1-illustration-poses.png)和[机器人四姿势](./art/robot-v1-illustration-poses.png)非像素插画图集。生产机和场景仍是像素占位美术。游戏内打开底部“数据状态”面板即可切换；原生程序把选择保存在游戏存档，浏览器模拟预览保存在该浏览器的本地存储。

## 资源目录

```text
app/public/skins/
  catalog.json             # 可选皮肤的 ID、名称及默认皮肤
  mint/
    manifest.json          # 帧位置、动作和画面锚点
    sprites.png            # 透明 PNG 图集
  peach/
    manifest.json
    sprites.png
  concept/
    manifest.json          # 薄荷对象图集 + 主角、机器人插画配置
    sprites.png            # 机器、棒、平台等像素占位对象及兼容帧
    hero-actions.png       # 主角六姿势透明插画图集
    robot-actions.png      # 机器人四姿势透明插画图集
```

资源随前端一起打包，Windows 与 macOS 共用。已安装的程序不能靠修改源码目录立即增加皮肤；新增或替换资源后需重新构建。当前不支持从用户目录导入外部皮肤。

## 新增或替换一套皮肤

1. 复制一套现有皮肤目录，改为新的小写英文/数字/连字符 ID，并在 `catalog.json` 登记名称与 ID。也可以直接替换现有目录的 `sprites.png` 与 `manifest.json`。
2. 绘制透明 PNG 图集，在 `manifest.json` 的 `frames` 中写入每帧的 `[x, y, 宽, 高]`。每个动作通过帧名列表与 `fps` 选择播放帧；静态图也写成只有一帧的动作。
3. 保留 `girl`、`robot`、`machine` 的动作键，以及 `floor`、`tray`、`bar` 的静态图键。主角需要 `idle/take/eat/beam/hit/victory`；机器人需要 `entering/ready/hit/defeated`；机器需要 `idle/active`。
4. `anchors.girl`、`anchors.robot` 是像素精灵帧内以像素计的脚底锚点。画面中人物的世界坐标仍由游戏控制；换图时保持脚底、取棒手和发射手的位置与现有画面接近，避免悬空或错位。`effects` 的 `beam`、`token`、`progress` 使用 `#RRGGBB`，分别给射线、输入粒子和机器进度条配色。
5. 在 `app/` 运行 `npm run check:config`，再运行 `npm run dev` 预览。检查浅色、深色桌面背景，尤其是取棒、吃棒、发射、受击与落堆动作。发布版本需重新构建安装包。

若要使用完整非像素主角，在清单中设置可选的 `illustration` 对象：`atlas` 指向同目录透明 PNG；`displayHeight` 是 320×128 逻辑画布中的整帧高度；`frames` 将帧名映射为 `[x, y, 宽, 高]`，所有帧尺寸必须一致；`anchor` 是每帧内的脚底坐标。`animations` 必须定义 `idle/take/eat/beam/hit/victory`，每项包含 `frames` 帧名列表和 `fps`。插画存在时，主角所有战斗阶段都使用插画图集；`girl` 像素帧仍需保留，供资源格式校验和其他对象复用。

`interactions.takeBarEndOffset` 与 `interactions.beamStartOffset` 是相对主角世界坐标的 `[x, y]` 偏移，分别控制移动能量棒的取用终点和程序射线的起点。现版为 `[-28, -19]`、`[32, -38]`；更换角色造型时需按手的位置调整，并在游戏中检查棒与手、射线与手是否接上。原先仅支持待机的 `idleIllustration` 格式已被完整动作图集取代，旧版资源包需迁移为 `illustration` 格式。

非像素机器人由可选的 `robotIllustration` 对象配置，沿用 `atlas`、`displayHeight`、`frames`、`anchor` 与 `animations` 格式；动作必须包含 `entering/ready/hit/defeated`。`beamImpactOffset` 是相对机器人世界坐标的 `[x, y]`，控制射线击中屏幕的位置，现版为 `[-15, -48]`。切换到没有机器人插画的皮肤时会恢复原像素精灵的比例与锚点。`robot` 像素帧仍须保留以满足当前皮肤格式。

当前画布为 320×128、渲染分辨率为 2 倍；PNG 使用透明背景。像素图集采用最近邻采样，插画图集采用线性采样。像素动作保留固定帧槽：主角 96×80、机器人 64×80、机器 80×64、能量棒 20×10、托盘 40×8、平台 320×16；插画主角与机器人均使用 600×520 帧槽，显示高度分别为 78、82 逻辑像素。形象可以在帧槽内重新设计，图集中的摆放位置可变；同一角色的各动作共用脚底锚点。

薄荷与蜜桃图集的可编辑源是 [`app/tools/generate-placeholder-skins.py`](../app/tools/generate-placeholder-skins.py) 与主角绘制模块 [`app/tools/draw_hero_v1.py`](../app/tools/draw_hero_v1.py)，运行前者需要 Python Pillow。插画的原始[主角六姿势设定板](./art/hero-v1-actions-sheet.png)、[机器人四姿势设定板](./art/robot-v1-actions-sheet.png)及各自同名的 `.prompt.txt` 提示词保存在仓库。[`make_illustration_actions.py`](../app/tools/make_illustration_actions.py) 和 [`make_illustration_robot.py`](../app/tools/make_illustration_robot.py) 分别负责抠图、脚底对齐、生成图集与预览；从空目录重建时先运行主角脚本再运行机器人脚本。它们需要 Pillow、NumPy 和 SciPy；普通构建不需要 Python。正式美术可继续补画过渡帧并更新图集、帧清单和交互点。

## 存档与回退

旧存档没有皮肤字段时默认使用“薄荷机房”。切换皮肤只保存 ID，不改玩法资源；如果后续版本移除了某套皮肤或文件损坏，启动时尝试显示默认皮肤，并在状态面板提示原因。内置皮肤切换时会先加载资源、再保存选择；加载失败则保留原皮肤。
