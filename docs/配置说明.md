# Feed Me Token 配置说明

游戏数值的单一来源是 [`app/game-config.json`](../app/game-config.json)。Rust 从该文件嵌入玩法规则，TypeScript 从同一文件导入玩法、动画和浏览器预览参数。默认值保持当前 MVP 行为。

美术图集及皮肤选择另见[皮肤资源说明](./皮肤资源说明.md)。`npm run check:config` 会同时校验数值和内置皮肤资源。

## 如何修改

1. 修改 `app/game-config.json` 中的数字，保留 JSON 结构和字段名。所有字段都是安全整数；除下表注明可为 0 的字段外，必须大于 0。
2. 在 `app/` 目录运行 `npm run check:config`。前端的 `npm run dev` 和 `npm run build` 也会自动执行该校验；`cargo test --offline` 可检查 Rust 能否读取内嵌规则。
3. 重新构建或重新启动开发程序。配置在构建时嵌入应用，**修改 JSON 不会实时改变已安装的程序**；发布新数值需要重新打包。安装包不读取用户目录中的自定义配置。

例如，将 `rules.tokensPerBar` 从 `1000` 改为 `2000`，重新构建后，新增的每 2,000 token 才会兑换一根能量棒，机器进度条和浏览器预览也使用同一阈值。

## 玩法规则 `rules`

| 字段 | 默认值 | 作用 |
| --- | ---: | --- |
| `tokensPerBar` | 1000 | 每根能量棒所需的新增 `total_tokens`，不足部分结转。 |
| `startingLevel` | 1 | 新存档的角色等级。 |
| `startingAttackPower` | 1 | 新存档的初始攻击力。 |
| `startingWave` | 1 | 新存档从第几波开始。 |
| `enemyBaseHp` | 1 | 第 1 波敌人的生命。第 `n` 波生命为 `enemyBaseHp + floor((n - 1) / enemyHpEveryWaves)`。 |
| `enemyHpEveryWaves` | 20 | 每经过多少波，敌人生命增加 1。 |
| `coinsPerDefeat` | 1 | 击败敌人获得的金币；允许为 0。 |
| `xpPerDefeat` | 3 | 击败敌人获得的经验；允许为 0。 |
| `xpPerLevel` | 10 | 升下一级所需经验为“当前等级 × 此值”。 |
| `upgradeCostPerAttackPower` | 5 | 攻击升级价格为“当前攻击力 × 此值”。 |
| `attackPowerPerUpgrade` | 1 | 每次购买升级增加的攻击力。 |

一次攻击固定取用 **1 根**能量棒，角色动作也按一根棒绘制；该约束暂未开放成配置。

## 节奏 `timing`

| 字段 | 默认值 | 单位与作用 |
| --- | ---: | --- |
| `usageRefreshMs` | 60000 | 毫秒；原生程序自动读取 Codex 用量的间隔。建议不低于 1000。 |
| `enemyWalkPixelsPerSecond` | 95 | 逻辑画布像素/秒；机器人入场速度。 |
| `productionBatchMs` | 750 | 毫秒；一次机器生产表演的时长。 |
| `takeMs` | 480 | 毫秒；主角取棒动作。 |
| `eatMs` | 550 | 毫秒；主角吃棒动作。 |
| `beamMs` | 300 | 毫秒；发射射线到结算攻击。 |
| `defeatMs` | 320 | 毫秒；敌人被击败后的熄屏反馈。 |
| `hitMs` | 250 | 毫秒；敌人存活时的受击反馈。 |
| `retryAfterHitMs` | 220 | 毫秒；敌人未死时再次取棒前的停顿。 |
| `activeFps` | 30 | 帧/秒；战斗、入场或生产时的绘制上限，最大 60。 |
| `idleFps` | 8 | 帧/秒；无动画时的绘制上限，不得高于 `activeFps`。 |

## 画面 `display` 与预览 `preview`

| 字段 | 默认值 | 作用 |
| --- | ---: | --- |
| `display.individualBarsPerRefresh` | 4 | 单次刷新逐根展示的产量；更多产出合批入堆。允许为 0（全部合批），最大 20。 |
| `display.maxPileBars` | 9 | 堆中最多画出的能量棒数量，最大 12；底部控制栏始终显示准确库存。 |
| `preview.startingBars` | 5 | 浏览器预览初始模拟能量棒；允许为 0。原生新存档始终从 0 开始。 |
| `preview.tokensPerRefresh` | 2500 | 浏览器预览每次手动刷新模拟增加的 token；允许为 0，不读取 Codex。 |

## 旧存档与边界

- 修改 `startingLevel`、`startingAttackPower` 或 `startingWave` 只影响新存档；已有等级、攻击力、波次和库存继续保留。
- 修改 `enemyBaseHp` 或 `enemyHpEveryWaves` 后，已有存档的当前敌人生命会在加载时被压到新波次的生命上限，不会主动补血。
- 修改 `tokensPerBar` 后，已有存档的 token 兑换余数会按新阈值继续计算；这不是全量重算，也不会补发过去已兑换的能量棒。正式调整兑换率前应另行决定存档迁移规则。
- 金币、经验、升级价格和动画节奏的新数值，从新版本中的后续战斗或动作开始生效；已获得的奖励不重算。
- 窗口尺寸、画面元素的世界坐标和音效音高仍在程序或 `src-tauri/tauri.conf.json` 中，不属于这份玩法配置；皮肤图集帧、锚点及部分特效颜色在各皮肤的 `manifest.json` 中。
